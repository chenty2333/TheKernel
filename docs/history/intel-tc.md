# Type-C display helpers

`crates/ax/tk-intel-display/src/tc.rs` keeps portable Type-C port-state predicates, mode names, HPD-glitch policy, FIA pin-assignment decoding, source lane-count selection, TC lane-domain selection, modular-FIA index selection, live-status legacy-flag fixup and legacy-AUX-domain comparison, and the existing ADL-P TC-DKL readout/signal-level helpers. The mode and lane functions follow Linux 7.2.3 `drivers/gpu/drm/i915/display/intel_tc.c` and accept already-read state rather than owning MMIO or power references.

The kernel still lacks the full i915 TC port object/state machine: port mutex/refcount lifetime, runtime-PM/wakeref ownership, workqueue disconnect/link reset, legacy/DP-alt/TBT connect/disconnect, runtime cold-block acquisition/release, TC PHY ops implementations for all platforms, DP/USB mux updates, runtime pin assignment refresh from MMIO and actual hotplug hooks are not wired; only its field decode/configuration helpers are translated. The current DKL output path remains limited to its already-owned ADL-N firmware route.


`tc_state_machine.rs` now contains the source-ordered display-12/13 TC mode, HPD, FIA ownership, connect/disconnect, link-refcount, reset-work, and suspend algorithms behind `TcStateIo`; it translates 95/96 functions applicable to this target. The remaining C pointer cast is replaced by `TcPortState`. A kernel-side `TcStateIo` implementation that pins real power domains, orders the DKL/FIA MMIO, binds work items, and invokes the new state machine from probe/HPD/atomic modeset is still required; the module declaration alone does not mean those runtime flows are active.
