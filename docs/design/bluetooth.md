# Intel Bluetooth on the USB transport

The `tk-bt-hci` crate provides checked HCI packet framing and channel ownership, plus initial translation of `iwmbtfw` firmware handling. The xHCI probe binds USB class `e0/01/01`, requires HCI event/ACL endpoints, and registers a control/interrupt/bulk transport in the axdriver registry. The kernel recognizes `AF_BLUETOOTH/SOCK_RAW/BTPROTO_HCI`; raw/user binds route command and event I/O to attached adapters, monitor frames use an HCI monitor header, and `HCIGETDEVLIST`/`HCIGETDEVINFO` expose basic device identity. ACL send is routed; ACL reception is not yet multiplexed to HCI sockets. `/sys/class/bluetooth/hciN` publishes identity and status attributes; negotiated features, full stats and monitor metadata remain limited.

The sources are FreeBSD `usr.sbin/bluetooth/iwmbtfw/iwmbt_fw.c`/`.h`/`main.c`, `iwmbt_hw.c`, and `sys/netgraph/bluetooth/drivers/ubt/ng_ubt.c` (BSD-2-Clause, 2026-10-08 snapshot). The translated firmware functions include `iwmbt_get_fwname`, `iwmbt_get_fwname_tlv`, `iwmbt_parse_tlv`, `iwmbt_is_supported`, `iwmbt_hci_command`, Intel version/boot-parameter queries, RSA/ECDSA header chunks, SFI command chunking/reset, DDC and event mask operations. On rootfs readiness the N305 8087:0033 (9260-family) path requests the TLV-named SFI/DDC using the kernel firmware service and initiates upload. To stage binary firmware into the guest image, set `THEKERNEL_INTEL_BT_FIRMWARE_DIR` to a linux-firmware `intel/` directory; `scripts/build-rootfs.sh` decompresses SFI/DDC files and carries `LICENSE.intel`. The 7260/8260 variants, full `main.c` recovery/status path and real-hardware verification remain incomplete. The HCI endpoint split maps control commands, interrupt events and bulk ACL to CrabUSB transfers. `no_device_ioctl` plus the kernel HCI socket path support an empty device list and raw/user/monitor channels; `HCIGETDEVINFO` is basic and controller event/ACL multiplexing is incomplete. `/sys/class/bluetooth/hciN` has basic identity/status attributes. Firmware blobs are not checked in.

The eventual USB driver should bind the Bluetooth HCI interface class, send command packets on endpoint zero, receive events on interrupt IN, and carry ACL over bulk IN/OUT. The socket/UAPI side must use Linux-compatible structures and errno behavior without translating GPL `net/bluetooth` implementation code. Present evidence is crate-level framing/parser tests only; no xHCI device or guest Bluetooth command has been exercised.
