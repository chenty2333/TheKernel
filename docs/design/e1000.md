# Intel e1000/e1000e/igb port

The shared Intel register/mask layer is translated from FreeBSD
`sys/dev/e1000/e1000_regs.h` and `e1000_defines.h` at
`c2b7fe4a9e94a0edba9dd2772874928b565c4f9e` (BSD-3-Clause). The FreeBSD
`if_em.c` `em_vendor_info_array[]` contributes all 193 Intel PCI device IDs
(BSD-2-Clause) to the default product PCI matcher. The BAR/PCI adaptation is
in `tk-axdriver::e1000`; queue and descriptor operations are in
`tk-axdriver-net::e1000` and use `NetDriverOps` with one TX/RX queue.

The FreeBSD `e1000_api.c` dispatch layer is translated to typed
`E1000ApiHardware` callbacks in `e1000::api`, including exact PCI-ID to
generation mapping and `setup_init_funcs()` ordering. Family MAC/PHY/NVM
callbacks remain to be wired to the per-generation hardware context; an uninstalled optional
callback retains the source's success/config-error fallback rather than
fabricating hardware behavior.

All 57 C function definitions in FreeBSD `e1000_mac.c` now have a Rust
`upstream:` counterpart in `e1000::mac` (1859 Rust lines for the 2376-line C
source file). Generic bus/flow-control/link-state, RAR/VFTA/MTA, semaphore,
LED, adaptive-IFS, and counter logic uses small MMIO/PCI/NVM/PHY traits or
explicit callback arguments. This is source-file coverage, not a claim that
every generation-specific callback is already installed in `E1000Nic`.

The PHY source translation has begun in `e1000::phy`: generic PHY callback
defaults/no-op methods, reset-block query, ID/revision reads, DSP reset, and
PHY retry counter adapters, MDIC, PHY I2C/SFP transfers, autonegotiation,
Kumeran and paged PHY access, polling, master/slave control, copper
autonegotiation, PHY ID/type discovery, IGP3 init script, M88/IGP2
cable-length, downshift, polarity, forced-speed/duplex, reset, copper
power-state, 82577/M88 copper setup, generic IGP/copper link setup, IGP/M88/IFE
forced-speed, D3 LPLU, PHY-info extraction, BM/HV/GS40G/mPHY/XMDIO accessors,
BM wakeup-register operations, and 82577 forced/info/cable paths cover 98 of 98
`e1000_phy.c`
functions so far.

The translated paths currently include bounded 82540 reset, RAR0 MAC-address
read, descriptor ring setup, RX refill, TX submit/completion reclaim, and
single-fragment RX completion. DMA buffers use the platform allocator and are
kept alive until software reclaims completed slots. The driver polls device
status; it does not import iflib, ifnet, bus_dma, or FreeBSD interrupt glue.

Not yet translated: exact per-generation MAC/PHY/NVM function-pointer families,
remaining PHY-generation negotiation workarounds, EEPROM initialization beyond
the generic helpers, full
interrupt service/card-reset lifecycle, multiple queues, checksum/VLAN/TSO
offloads, VF/mailbox, and power-management hooks. The current 2048-byte packet
path intentionally uses single-buffer frames and no offloads. QEMU acceptance
for e1000/e1000e/igb is pending.

The first OS-dependent layer is now isolated in `e1000::osdep`: PCI command/
PCIe capability helpers and the 82579 PCIm2PCI arbiter/tail-write workaround use
small PCI/MMIO traits. FreeBSD `SYSINIT(enable_pause_delay)` is module-loader
glue; TheKernel uses bounded busy-wait delays, not sleepable `pause()` from
register/interrupt contexts.

The shared EEPROM/NVM translation is in `e1000::nvm`: all 31 upstream C
function definitions have `upstream:` Rust counterparts, covering Microwire/SPI
clocking, EERD polling, lock/release callbacks, PBA data/image helpers,
checksum, RAR MAC extraction and firmware-version decoding. Bus access and NVM
locking are isolated behind narrow traits; device-family callback installation
and EEPROM writes from the live NIC attach path remain separate integration
work. PBA image helpers preserve the source's word layout and reject out-of-
range images rather than dereferencing an invalid pointer.

The FreeBSD `e1000_manage.c` helpers are translated in `e1000::manage` with
all 10 C definitions represented. Host SRAM access and device policy inputs are
provided by small traits/values, while command checksums, unaligned payload
writes, host-interface polling, manageability state, DHCP command emission and
firmware window programming retain their source sequences.

The 82540/82545/82546 family port in `e1000::chip82540` represents all 14
`e1000_82540.c` functions, including Microwire geometry, M88 PHY validation,
family reset's IO-write workaround, fiber/serdes amplitude/VCO setup, copper
link sequence, 82540 counters, and EEPROM-derived MAC address. Low-level
family callbacks are expressed as traits so the common code can be bound to
TheKernel MMIO/NVM/PHY adapters without importing FreeBSD function-pointer
structures.

`e1000::chip82541` covers all 20 function definitions from `e1000_82541.c`:
SPI/Microwire NVM geometry, IGP PHY selection and cable table, DSP/FFE link
state, reset/init, D3 LPLU, LED handling, and EEPROM MAC reads. Hardware
subsystems are callback traits over existing MMIO/NVM/PHY abstractions; family
initializers are not yet selected by the live `E1000Nic` attach path.

`e1000::chip82542` maps all 14 upstream function definitions, including the
82542 register-offset translation table, legacy RAR encoding, Microwire layout,
revision-2 MWI/reset sequencing, flow-control compatibility rules, LEDs,
counters and EEPROM MAC-address read. PCI MWI and reset/NVM/common setup paths
are explicit callbacks rather than imported FreeBSD PCI glue.

`e1000::chip82543` contains `upstream:` counterparts for all 32
`e1000_82543.c` functions: software-MDIO bit-banging, 82543/82544 PHY reset
and link branches, TBI compatibility/SBP statistics repair, VFTA write
workaround, legacy flow through init/reset, LED, counters, and NVM MAC reads.
Platform-independent state and hardware operations are modeled with typed
state and callback traits; live family dispatch remains an integration step.

The 82571-family translation in `e1000::chip82571` has all 36 source function
names represented, including 82571/72/73/74/83 PHY/NVM dispatch, flash checksum
commit/fix, software and MDIO semaphores, D0/D3 LPLU, reset/init workarounds,
serdes state handling, VLAN preservation, LED defaults, LAA handling and
counter clearing. NVM/PHY/PCI lifecycle edges are callback-driven; the live NIC
has not yet selected these family callbacks.

The 82571-family implementation in `e1000::chip82571` maps all 36 upstream
function definitions: PHY/NVM geometry by generation, software/MDIO semaphore
paths, EERD/EEWR and SPI writes, flash checksum commit/repair, PHY reset and
LPLU, reset/init workarounds, serdes state transitions, LAA/VLAN/LED helpers,
and counters. Trait callbacks represent PCI/NVM/PHY lifecycle glue; these
callbacks are not yet installed on the live NIC probe path.

The 82575-family module `e1000::chip82575` has counterparts for all 72 C
function definitions (1,712 Rust lines for the 3,540-line C source). It covers
SGMII/MDIO PHY selection, NVM geometry/semaphore/checksum, PCS link and SFP
media selection, 82580/i350 checksum/VLAN quirks, M88 PHY setup, EEE, VMDQ,
PCIe completion timeout, and bit-banged I2C transfers. Register/NVM/PHY and
serial-bus interactions are expressed as typed adapter traits; live hardware
family callback installation is still pending.

`e1000::chip80003es2lan` contains counterparts for all 30
`e1000_80003es2lan.c` definitions (776 Rust lines / 1,452 C lines), including
per-port software/firmware semaphores, GG82563 alternate-page MDIC workarounds,
Kumeran CSR locking/timing and 10/100-vs-1000 link adjustments, reset/init,
PHY cable-length table, MAC/NVM, and counter paths. PCI/NVM/common link lifecycle
is represented by narrow platform adapters and remains to be wired to the live
NIC family selector.

The ICH/PCH integrated LAN file is represented by `e1000::chipich8` with
counterpart markers for all 96 unique definitions reported by `ctags` for
`e1000_ich8lan.c` (the task's source-count inventory reports 99; the three
additional entries do not resolve to unique definitions in this source
revision). This includes flash-cycle and shadow-NVM paths, bank/checksum
handling, PCH PHY/LED/power workarounds, link setup, RAR/MTA, reset/init, LTR,
and jumbo-frame logic. Explicit register/PHY/flash and lifecycle traits stand
in for FreeBSD bus and operation tables. These family callbacks are not yet
installed on the live NIC attach path.

The i210/i211 `e1000_i210.c` port is in `e1000::i210` (22/22 unique source
definitions). It adds bounded SW/FW and SMBI semaphore access, EERD/EEWR bursts,
iNVM record walking/version decode, checksum/flash commit, LED defaults, config
done, and the PHY PLL restart sequence. PCI power-state operations, NVM backend
and PHY transactions are represented by narrow adapters; live generation
dispatch is still pending.

The 32 definitions in `e1000_mbx.c` are represented by `e1000::mbx`: generic
posted-message timeout behavior, VF read-to-clear shadow handling, VF ownership,
PF VF request/ack/reset causes, shared VMBMEM transfers, and per-side counters.
The mailbox protocol is available to family adapters; the current generic NIC
does not expose SR-IOV PF/VF mailbox services.

The `if_em.c` adapter module has begun in `e1000::if_em`. Its current 36
counterparts cover queue caps, interrupt moderation deltas/rate selection,
generation memory-error policy/configuration/statistics, MTU bounds, TSO capability masking policy,
and EEE/MAC validity predicates. iflib/newbus/sysctl methods are not copied;
their applicable behavior still needs to be mapped into `NetDriverOps` and
TheKernel's current PCI/interrupt/DMA lifecycle.

The current `if_em` marker set has grown to 103/164 unique definitions. Added
direct MMIO helpers cover VF/PF and device-reset interrupt gates, transmit
ring and unit setup, receive ring/control/RSS setup, PBA/flow-control reset
policy, manageability ownership, and periodic hardware counters. Ring DMA
addresses and PF/PCI lifecycle remain adapter inputs; VLAN/promiscuous state,
VF statistics, mailbox wake/reset state, and generic interrupt/datapath paths
also have explicit Rust helpers, as do per-generation RX/TX ring initialization,
DMA coalescing and 8254x SmartSpeed state. Dynamic iflib contexts are
intentionally not imported.

The `e1000_vf.c` helpers are translated in `e1000::vf` (21/21 unique
definitions): VF-only operation defaults, reset and PF MAC handshake, link
status, primary/secondary unicast, multicast hash packing, VLAN, LPE and
promiscuous mailbox requests. They are software helpers only; probe-family
selection and a PF-backed VF runtime are not part of the current NIC path.

The `if_em.c` adapter now has source-marker counterparts for 107 of the 164
unique function definitions found by `ctags` in this source revision. The added
helpers preserve the 82574/82575-family IVAR/EIMS queue routing, media selection
and reported media state, and flow-control mode validation. The source inventory
counts 186 entries, including 22 framework callback definitions not returned as
unique `ctags` function definitions. Remaining register, wake, PCI-PM and
interface lifecycle work is not considered complete; pure `iflib`/newbus/sysctl
registration is excluded from the port.

The `if_em.c` translation now includes 115/164 unique `ctags` functions.
Recent additions preserve 82574 NVM MSI-X count repair, IGB interrupt mask
ownership (including VF-shared MSI-X bits), wake-link/LED sequencing, PCH sleep
ULP/EEE PHY accesses and legacy/IGB firmware-version decoding. PHY/PCI/NVM and
interrupt scheduling remain explicit adapter inputs; system WoL entrypoints and
TheKernel PM capability support are still unfinished.

`if_em.c` coverage is now 116/164 unique `ctags` functions. The admin-status
adapter models fatal/device-reset gates, copper/fiber/SerDes link sampling and
transitions, deferred reset/publication, timer-sampled statistics, 82574 PHY
hang recovery, 82571 LAA restoration and legacy SmartSpeed callback ordering.
The PCI binding now selects advanced queues from the detected shared MAC type,
so 82575-and-newer devices do not incorrectly enter legacy descriptor mode.

The admin polling path now has an `em_if_timer()` counterpart: only queue zero
marks hardware counters pending and schedules the deferred admin task, matching
iflib's shared timer callback without importing its task framework.

`em_get_wakeup()` is represented by an explicit NVM/PCI policy adapter: it
selects the NVM offset and APME byte by MAC generation and PCI function,
handles PCH WUC PHY-wake state, board/port restrictions and the multi-adapter
quad-port cursor, then derives WOL capabilities and magic-packet default.

`em_enable_wakeup()` now models WUFC filter selection, multicast wake-table
policy, receive-control restoration, D3 wake advertisement, PCH PHY/MAC wake
path selection, PME control and bus-master fencing. PHY/PCI-PM operations remain
adapter calls because the current net-device API has no system-suspend/WoL
lifecycle hook; the state machine is unit tested for success and rollback.
