# Intel e1000/e1000e/igb port

The shared Intel register/mask layer is translated from FreeBSD
`sys/dev/e1000/e1000_regs.h` and `e1000_defines.h` at
`c2b7fe4a9e94a0edba9dd2772874928b565c4f9e` (BSD-3-Clause). The FreeBSD
`if_em.c` `em_vendor_info_array[]` contributes all 193 Intel PCI device IDs
(BSD-2-Clause) to the default product PCI matcher. The BAR/PCI adaptation is
in `tk-axdriver::e1000`; queue and descriptor operations are in
`tk-axdriver-net::e1000` and use `NetDriverOps` with one TX/RX queue.

The FreeBSD `e1000_api.c` dispatch layer is translated to typed
`E1000ApiHardware` callbacks in `e1000::api`, including exact PCI-ID to
generation mapping and `setup_init_funcs()` ordering. Family MAC/PHY/NVM
callbacks remain to be wired to the per-generation hardware context; an uninstalled optional
callback retains the source's success/config-error fallback rather than
fabricating hardware behavior.

All 57 C function definitions in FreeBSD `e1000_mac.c` now have a Rust
`upstream:` counterpart in `e1000::mac` (1859 Rust lines for the 2376-line C
source file). Generic bus/flow-control/link-state, RAR/VFTA/MTA, semaphore,
LED, adaptive-IFS, and counter logic uses small MMIO/PCI/NVM/PHY traits or
explicit callback arguments. This is source-file coverage, not a claim that
every generation-specific callback is already installed in `E1000Nic`.

The PHY source translation has begun in `e1000::phy`: generic PHY callback
defaults/no-op methods, reset-block query, ID/revision reads, DSP reset, and
PHY retry counter adapters, MDIC, PHY I2C/SFP transfers, autonegotiation,
Kumeran and paged PHY access, polling, master/slave control, copper
autonegotiation, PHY ID/type discovery, IGP3 init script, M88/IGP2
cable-length, downshift, polarity, forced-speed/duplex, reset, copper
power-state, 82577/M88 copper setup, generic IGP/copper link setup, IGP/M88/IFE
forced-speed, D3 LPLU, PHY-info extraction, BM/HV paged-register accessors,
BM wakeup-register operations, and 82577 forced/info/cable paths cover 89 of 98
`e1000_phy.c`
functions so far.

The translated paths currently include bounded 82540 reset, RAR0 MAC-address
read, descriptor ring setup, RX refill, TX submit/completion reclaim, and
single-fragment RX completion. DMA buffers use the platform allocator and are
kept alive until software reclaims completed slots. The driver polls device
status; it does not import iflib, ifnet, bus_dma, or FreeBSD interrupt glue.

Not yet translated: exact per-generation MAC/PHY/NVM function-pointer families,
remaining PHY-generation negotiation workarounds, EEPROM initialization beyond
the generic helpers, full
interrupt service/card-reset lifecycle, multiple queues, checksum/VLAN/TSO
offloads, VF/mailbox, and power-management hooks. The current 2048-byte packet
path intentionally uses single-buffer frames and no offloads. QEMU acceptance
for e1000/e1000e/igb is pending.

The first OS-dependent layer is now isolated in `e1000::osdep`: PCI command/
PCIe capability helpers and the 82579 PCIm2PCI arbiter/tail-write workaround use
small PCI/MMIO traits. FreeBSD `SYSINIT(enable_pause_delay)` is module-loader
glue; TheKernel uses bounded busy-wait delays, not sleepable `pause()` from
register/interrupt contexts.
