## Performance Priorities

Current score planning still uses the user-provided leaderboard/local score
snapshot in `docs/score-tracking.md`, but this replay adds two concrete local
blockers:

1. Fix LA `iozone-glibc` stride-read timeout first. It blocks the rest of the LA
   full replay and directly targets the iozone performance gap. Focus on
   LoongArch VFS, page cache, read path, file offset handling, forked worker I/O,
   and scheduler/wakeup behavior under four iozone processes.
2. Fix RV `fallocate02` allocator panic. It unlocks the rest of current
   `ltp-glibc` plus any later `ltp-musl` evidence in full replay order.
3. Attack high-fanout RV LTP clusters: futex compare/requeue, fcntl variants,
   `copy_file_range`, permission/ownership errno behavior, epoll/inotify/time,
   and scheduler attribute validation.
4. Keep already-passing benchmark groups protected while optimizing measured
   paths: iozone, lmbench, libcbench, iperf/netperf, and cyclictest remain below
   the observed leading-team target shape.

Do not treat a group as complete merely because it prints an END marker. For
performance groups, compare the local measured score against the observed target
shape before removing it from the backlog.
