# Authored ACPICA policy fixtures

These small SSDTs are original TheKernel regression data, **not captured OEM
firmware**. `thermal.asl` starts below critical and reaches `_CRT` ten seconds
after its first `_TMP` evaluation. It must only be injected into QEMU.

Regenerate with the pinned ACPICA 20260930 `iasl -p OUTPUT STEM.asl`. The checked-in
AML permits the QEMU regression without a host tool installation.

Run `scripts/ci/acpica-policy-qemu-smoke.py` with a private TheKernel state directory,
`CARGO_BUILD_JOBS=6` and `nice -n 10`. It uses the formal product builder/runner,
checks live thermal sysfs values, and requires critical -> ordered flush -> AML
S5. Shell EOF, QMP quit and host termination are not accepted as trip proof.

`button.asl` registers a wake-capable S0 GPE and emits Notify 0x80 from `_INI`.
Its bounded sleep lets the diagnostic stream drain before the early shutdown.
This proves the control-method consumer, not a QMP-produced control-method
button: q35's `system_powerdown` produces its fixed-function button.

The fixed-button case uses QMP after an actual shell readiness command, with init
held in a long sleep. `unsupported-ecdt.bin` is generated by the adjacent original
Python source: it deliberately describes unsupported SystemMemory EC resources.
The fallback case must still boot and complete QMP -> static SCI -> ordered S5,
without an ACPICA-ready or ACPICA-S5 marker. No raw firmware is used.

Default-path runs omit `acpi=acpica`. `unsupported-pci.asl` adds a deliberately
unsupported segment-one root: it fails after SCI takeover and must restore
static fixed-button shutdown without publishing native routes/ready. The
explicit `acpi=static` case validates the retained minimal rescue separately.
The INTx script additionally verifies a no-MSI/no-MSI-X NIC with external TCP
wire bytes and increasing IRQ counts, not an in-guest loopback echo.
